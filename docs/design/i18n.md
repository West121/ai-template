# 多语言（i18n）设计

> 立项（2026-07-16）：涵韬 OA 支持五语 —— **简体中文 zh-CN / 英文 en / 繁体中文 zh-TW / 泰语 th / 日语 ja**。
> 全站现为硬编码中文、无 i18n。本文照主控已拍板的框架细化落地方案、迁移分批与红线；**不 commit、不改代码**。
>
> 主控已拍板框架（本文照此细化，不推翻）：
> ①静态 UI 文案 = react-i18next + **中文即 key**（`t('保存')`，缺翻回退中文，可渐进迁移）；locale 存 app-store 持久化 + 顶栏切换器。
> ②动态数据 label = schema 旁挂 `labelI18n?: Record<locale,string>`（缺省回退原 label，现有表单零迁移），设计器加「多语言」编辑弹窗，渲染端按 locale 取。
> ③AI 一键翻译（弹窗内按钮生成其余四语 + 静态文件 agent 批量生成初稿）。
> ④后端消息 i18n 后置（M4 可选）。
> ⑤分批 M1 基建+表单级 labelI18n+AI 翻译 / M2 静态核心页 / M3 全站扫尾+其它动态 label / M4 后端。

## 二、locale 类型与回退链（拍板点③）

```ts
// stores/app-store.ts 扩展
export type Locale = "zh-CN" | "en" | "zh-TW" | "th" | "ja"
export const LOCALES: { value: Locale; native: string; dateFns: string }[] = [
  { value: "zh-CN", native: "简体中文", dateFns: "zhCN" },
  { value: "en",    native: "English",  dateFns: "enUS" },
  { value: "zh-TW", native: "繁體中文", dateFns: "zhTW" },
  { value: "th",    native: "ไทย",      dateFns: "th"   },
  { value: "ja",    native: "日本語",   dateFns: "ja"   },
]
// AppSettings 增 `locale: Locale`，默认 "zh-CN"；持久化在 oa-app-settings。
```

**回退链（建议，请拍板）**：因采用「中文即 key」，**zh-CN 无需资源文件**——key 本身就是简中显示。故：

- **静态 UI**：`当前 locale → 中文原文 key`。i18next `fallbackLng: "zh-CN"`，`zh-CN` bundle 置空 `{}`，i18next 命不中即回 key（=中文）。zh-TW 缺翻同样回退中文（不做机械繁简转换，见分叉②）。
- **动态 label**：`labelI18n[locale] → label（原字段=简中源）`。即 `pick(labelI18n, locale, label)`：
  ```ts
  export function pickLabel(labelI18n: Record<string,string> | undefined, locale: Locale, fallback: string): string {
    if (locale === "zh-CN") return fallback              // 简中恒取源字段
    const v = labelI18n?.[locale]
    return (typeof v === "string" && v.trim()) ? v : fallback  // 空/非字符串 → 回退中文
  }
  ```
  **zh-CN 永远取源 `label`，故 `labelI18n` 只承载其余四语**——现有表单无 `labelI18n` 即全回退，**零迁移**。

> 简化结论：五语的终极兜底都是**中文原文**，绝不出现空白/`[missing]`。这是防白屏红线（§五）。

## 三、设计

### 3.1 静态 UI：react-i18next + 中文即 key

**初始化**（新增 `web/src/lib/i18n.ts`，`main.tsx` 首屏前 import）：
```ts
import i18n from "i18next"
import { initReactI18next } from "react-i18next"
i18n.use(initReactI18next).init({
  lng: readLocaleFromAppStore(),      // 与 app-store.locale 同步
  fallbackLng: "zh-CN",               // zh-CN bundle 为空 → 命不中回 key(中文)
  resources: { "zh-CN": { translation: {} } },  // 其余四语懒加载注入
  keySeparator: false, nsSeparator: false,       // key 是整句中文，禁用分隔符解析
  returnEmptyString: false,
  interpolation: { escapeValue: false },
})
```
> `keySeparator:false`/`nsSeparator:false` 是**硬要求**：key 形如 `"长度不能少于 {{min}}"`，含 `:`/`.` 的中文句不能被当命名空间/层级切开。

**用法（渐进迁移，不需一次改完）**：
```tsx
const { t } = useTranslation()
<Button>{t("保存")}</Button>
toast.success(t("已全部标记为已读"))
// 插值：把 `长度不能少于 ${min}` 改为 t("长度不能少于 {{min}}", { min })
```
未迁移的裸中文继续正常显示（就是 zh-CN），迁移一处生效一处——**允许全程灰度**。

**locale 切换联动**（切换器 onSelect 里一次做齐）：`app-store.setLocale(l)` → `i18n.changeLanguage(l)`（首次触发懒加载该语 bundle）→ 设置 date-fns locale（§3.7）→ 可选 `document.documentElement.lang = l`。

**资源组织（视规模的建议）**：
- 起步：**每非中文语言一个扁平 JSON**（`web/src/locales/en.json`、`zh-TW.json`、`th.json`、`ja.json`），`key=中文原句`、`value=译文`；locale 切换时 `import()` 懒加载 + `i18n.addResourceBundle`。zh-CN 不建文件。
- 规模阈值：单文件 > ~200KB 或 key > ~2000 时，再按顶层模块拆命名空间（`common/workflow/system/bizdoc/…`）分包懒加载。**先简单，后拆分**。
- **抽取工具**：建轻量脚本 `scripts/i18n-extract.mjs` 扫 `t("…")` 调用汇成 key 目录（去重）；喂给 AI 批量产四语初稿（§3.6）。因 key 是整句中文，`i18next-parser` 适配差，**自研脚本更稳**（拍板⑤，属小分叉）。

### 3.2 动态 label：`labelI18n` 模型

**类型扩展**（`types/workflow.ts`）：
```ts
export interface FormWidget {
  label: string
  labelI18n?: Partial<Record<Locale, string>>   // 仅存 en/zh-TW/th/ja；缺 = 回退 label
  // …选项同理，可选给 option 挂 labelI18n（见分叉⑦）
}
export interface FormSchema {
  title?: string
  titleI18n?: Partial<Record<Locale, string>>
}
// FieldDescriptor（form-manifest.ts）后端派生清单同步加 labelI18n?（NON_NULL，缺省不下发）
```
**渲染端改造**（全部走 `pickLabel`，一处封装）：
- `form-renderer.tsx`：`{widget.label}` → `{pickLabel(widget.labelI18n, locale, widget.label)}`（约 6 处 + 校验文案）。
- `field-perms-editor` / `HostedForm` / 节点字段权限矩阵：消费 `FieldDescriptor.label` 处同改。
- **序列化零改动**：`labelI18n` 是纯附加字段，随 schemaJson 存取；旧 schema 无此键，`pick` 自然回退。

### 3.3 语言切换器

- **位置**：顶栏 `ThemeToggle` 左侧（搜索与全屏之后）。**图标** `Languages`（lucide；`Globe` 备选）。DropdownMenu 结构与 `ThemeToggle` 一模一样（复用其视觉/暗色两态/当前项高亮 `bg-accent text-primary`）。
- **五项以母语自显**：`简体中文 / English / 繁體中文 / ไทย / 日本語`（取 `LOCALES[].native`，**不翻译语言名**）。
- **镜像**：`settings-drawer` 增「语言 / Language」一节（同 `LOCALES`），提升可发现性；与顶栏共享 `app-store.locale` 单一真源。
- 移动端：并入 `UserMenu` 或抽屉，避免顶栏拥挤。

### 3.4 多语言编辑弹窗（labelI18n / titleI18n 编辑器）

**新增共享组件** `components/i18n/label-i18n-dialog.tsx`（设计器/未来菜单/节点名/字典通用）：

- **触发**：字段标签 Input（designer-core 行 669）右侧一枚小 `Languages` 图标钮；表单标题（表单设置弹窗行 1727）同法。已填任一非中文语言时钮上加一个圆点/角标提示"已配多语言"。
- **弹窗结构**（Dialog）：
  - 顶部一行**源文（简中，只读）**：`简体中文：请假天数`（源始终等于 `label`）。
  - 下方 **4 行**可编辑：`English / 繁體中文 / ไทย / 日本語`，各一 `Input` 绑定 `labelI18n[locale]`。
  - 右上 **「AI 翻译」按钮**：以源中文调 `POST /api/ai/translate`（§3.6），回填四个 Input（默认只填空行，可选"覆盖全部"）；加载态转圈；失败/离线走 mock 回显（`[en]请假天数` 之类）不阻断手填。
  - **空态回退提示**：每个空 Input 的 placeholder = `留空则显示中文原文`。
- **保存**：`onUpdate({ labelI18n })`，**剔除空串**（`labelI18n` 只留已填语言，保持 schema 精简）；全空则删 `labelI18n` 键。

### 3.5 AI 一键翻译 —— 契约（给磐石）

复用现有 AI 基建（`components/ai-chat/api.ts` 的 `withMock` 封装 + `/api/ai/*` 命名空间 + `{code,message,data}` 信封 + 模型档案 FAST/STANDARD）。前端新增 `lib/i18n-translate.ts`：

```
POST /api/ai/translate
请求体：{
  texts: string[],              // 待译中文原文（前端去重后提交）
  targetLocales: string[],      // ["en","zh-TW","th","ja"]，按需子集
  sourceLocale?: "zh-CN",       // 默认 zh-CN
  context?: string              // 可选领域提示，如 "OA 审批表单字段名，简短名词"，提升质量
}
响应 data：{
  translations: { [text: string]: { [locale: string]: string } }
}
```
- **前端行为**：照 `withMock` —— 离线 / 404 → mock（伪翻译回显，`demo:true`）；真实 4xx/5xx 抛出 toast。批量上限（如单次 ≤ 50 条）前端分片。
- **后端要点（磐石 + 主控拍板④）**：走 LLM（FAST/STANDARD 档）批量；权限门控（建议专码 `system:i18n:translate`，或沿用登录即可 —— 拍板）；无副作用、可重试；`targetLocales` 白名单校验。
- **静态文件批量**：`scripts/i18n-extract.mjs` 抽出 key 目录后，由 **agent / 一次性脚本**调同一端点（或 dev-time 直连 LLM）产 `en/zh-TW/th/ja.json` 初稿，人工校审后入库。**这是 dev-time 任务，非运行时**。

### 3.6 日期 / 数字本地化（date-fns，非 dayjs —— 见分叉①）

- 新增 `lib/datetime.ts`：按 `app-store.locale` 映射 date-fns locale（`zhCN/enUS/zhTW/th/ja`，均已在 node_modules），封装 `formatDate(d, fmt)` / `formatDateTime` 统一出口。改造点极少（现仅 `schedule` 引 locale + 4 处 `toLocaleString`）。
- 数字/金额：`Number.toLocaleString` 传当前 locale；**人民币大写 `toChineseAmount` 保持中文专用**（业务语义绑定 CNY，不做多语言，仅在 zh 场景显示）。

### 3.7 泰语 / 日语 UI 适配

- **字体栈**（`index.css` 根 `font-family` 追加，按 locale 兜底）：
  `-apple-system, "PingFang SC", "Microsoft YaHei", "Noto Sans JP", "Noto Sans Thai", "Hiragino Sans", sans-serif`。泰/日缺字时优先系统 Noto，无则回退。
- **文本膨胀**：英文约中文 **×1.3–1.5**，泰语可达 **×2**（无词间空格 + 上下叠加变音符号）。据此：
  - 菜单项 / 按钮 / 标签 / 徽标**禁用固定宽**，改 `min-w-*` + `truncate` + `title`/Tooltip 兜底（顶栏搜索框、`Wf_NOTIFY_TYPE` Badge、DataTable 表头是重灾区）。
  - 避免对可变文案用 `whitespace-nowrap` 造成溢出撑破容器。
- **行高与截断**：泰语变音符号叠字，`h-8` 单行 + 紧行高会**裁切上下标**。凡承载可变文案的单行控件，`line-height` 留白（≥1.5），或 `min-h` 代替死 `h-`；`truncate`（省略号）已广泛使用，保留。
- 验收：五语各截一屏顶栏 + 一个长菜单 + 一个审批详情，肉眼查裁切/溢出/换行。

## 五、红线（防白屏 / 冒烟，与既有四层对齐）

1. **缺翻恒回退中文，绝不空白**：静态 `fallbackLng:"zh-CN"`(空 bundle)→key；动态 `pickLabel` 空/非字符串→`label`。任何语言下不得出现 `[missing]`/空标签。
2. **`labelI18n` 非对象容错**：`pickLabel` 内 `typeof !== "string"` 即回退；`labelI18n` 是数组/字符串/null 一律当无（同「规则3：归一化多态 payload」）。渲染端**永不**直接 `labelI18n[locale]` 取值。
3. **资源懒加载失败不崩**：切语言时 `import()` json 失败 → 留在当前语言 + toast，不白屏。
4. **key 解析安全**：`keySeparator:false`/`nsSeparator:false` 防整句中文 key 被 `:`/`.` 切碎。
5. **冒烟**：切到 en/th/ja 各跑一遍现有 jsdom mount 冒烟（"renders without throwing"），确保切换语言不抛；新增 `pickLabel`/`i18n-extract` 纯函数单测（回退链、空 labelI18n、插值）。
6. **AI 翻译降级**：`/api/ai/translate` 离线/404 → mock，不阻断人工手填；真实错误 toast 不崩弹窗。

## 六、需主控拍板的分叉点

| # | 分叉 | 丹青建议 |
|---|---|---|
| ① | 主控框架写"**dayjs** locale 联动"，但仓库用 **date-fns v4**（五语 locale 已内置，零新增依赖） | **保留 date-fns**，封装 `lib/datetime.ts`；不为 i18n 引入 dayjs |

| ③ | `labelI18n` 是否存 zh-CN | **不存**：`label` 即简中源，`labelI18n` 只承载其余四语（保零迁移、省体积） |

| ⑦ | 选项/枚举 label：静态 key vs `labelI18n` | 设计器**静态选项**挂 option 级 `labelI18n`；代码内**枚举字典**（`WF_NOTIFY_TYPE_LABEL` 等）走静态 `t()` key |
| ⑧ | 菜单 title 走静态 key 还是 `labelI18n` | 走**静态 `t(title)`**（`menu.ts` 是代码常量，非用户数据），不引 `labelI18n` |
