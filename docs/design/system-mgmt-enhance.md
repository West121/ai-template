# 系统管理完善设计

> 用户需求(2026-07-12):用户管理改**左部门树+右用户**(部门也能增删改查);系统管理各页补**多选(批量)**+**序号列**——现状太简单。

## 现状(查证)
- 系统管理 9 页:dept/dict/file/job/log/menu/post/role/user。
- **用户管理**:单张 DataTable + 部门"拍平成下拉"筛选,**不是左树右表**。
- **DataTable**:已有 `selectionColumn`/`enableSelection`/批量操作悬浮区,但**各页大多没启用**;**无序号列**。

## 一、用户管理重构:左部门树 + 右用户列表
- **左:组织部门树**(展开/选中,当前部门高亮)+ **增删改查**(工具栏/右键菜单:新建部门、新建子部门、编辑、删除、设负责人)——复用 dept.tsx 的部门 CRUD 逻辑,收进树组件。
- **右:选中部门的用户列表**(DataTable):按选中部门过滤(带"含子部门"checkbox);选根/全部→全部用户;用户 CRUD(新增/编辑/删/重置密码/启停)+ **多选批量**。
- 布局:左树固定宽(可拖,持久化)+ 右表自适应;暗色两态;移动端上下堆叠或部门抽屉。防白屏(树/表各 ErrorBoundary)。

## 二、DataTable 序号列
- 新增 `indexColumn(pageIndex, pageSize)` helper:序号 = `pageIndex*pageSize + rowIndex + 1`(服务端分页对齐,非仅当前页行号);窄列、居中、不参与排序/隐藏。各表可选启用(放选择列后、数据列前)。

## 三、多选 + 批量操作全覆盖
- 各系统页启用 `enableSelection` + 批量操作区(现成悬浮胶囊):
  - 通用:**批量删除**、**批量启用/停用**(有 enabled 的)。
  - 用户额外:**批量移部门**、批量设角色/岗位、导出。
  - 日志:批量删除(清理)。
- **后端批量 API**:`POST /api/system/users/batch-delete`、`/batch-status`、`/batch-move-dept` 等(校验+权限 @PreAuthorize+不误删自己/超管);角色/岗位/字典同理 batch-delete。幂等、部分失败返回逐条结果。
